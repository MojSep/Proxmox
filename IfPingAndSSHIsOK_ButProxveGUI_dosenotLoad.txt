SSH و پینگ برقرار هستند اما وب‌سایت بالا نمی‌آید، این یعنی مشکل از شبکه یا خود هاست نیست، بلکه احتمالاً سرویس‌دهنده رابط وب (**`pveproxy`**) یا یکی از پیش‌نیازهای آن دچار مشکل شده است. در ادامه گام‌به‌گام این موارد را بررسی می‌کنیم.

### 🔍 گام ۱: بررسی اولیه و اتصال
*   **آدرس را دقیق بررسی کنید**: باید از **`https://`** (نه http) استفاده کنید و پورت **`:8006`** را در انتهای آدرس بنویسید (مثلاً `https://192.168.1.100:8006`). فراموش کردن این موارد شایع‌ترین علت است.
*   **بررسی پورت از خارج**: از سیستم خودتان دستور `nc -zv <IP-هاست> 8006` را اجرا کنید. اگر Connection refused داد، مشکل از سرویس یا فایروال است.

### 🛠️ گام ۲: بررسی سرویس `pveproxy` (مهم‌ترین گام)
با SSH وارد هاست شوید و بررسی کنید آیا سرویس روی پورت 8006 گوش می‌دهد یا خیر:
```bash
ss -tlnp | grep 8006
```
**اگر خروجی خالی بود**، یعنی سرویس `pveproxy` اجرا نشده است. وضعیت آن را بررسی و ری‌استارت کنید:
```bash
systemctl status pveproxy  # مشاهده وضعیت و خطا
systemctl restart pveproxy # تلاش برای راه‌اندازی مجدد
```
اگر سرویس بلافاصله بعد از ری‌استارت دوباره قطع شد، لاگ‌ها را با `journalctl -u pveproxy -n 50 --no-pager` بررسی کنید تا علت دقیق را ببینید.

> **نکته**: گاهی سرویس‌های وابسته (مثل `pvedaemon` و `pve-cluster`) مشکل دارند و باعث خطای `pveproxy` می‌شوند. وضعیت آن‌ها را هم با `systemctl status` بررسی کنید.

### 🧱 گام ۳: بررسی فایروال
فایروال داخلی Proxmox (که از iptables/nftables جدا است) ممکن است پورت 8006 را مسدود کرده باشد:
```bash
cat /etc/pve/firewall/cluster.fw | grep enable  # بررسی فعال بودن
iptables -L -n | grep 8006                     # مشاهده قوانین مرتبط
```
برای تست سریع، می‌توانید موقتاً فایروال را خاموش کنید:
```bash
pve-firewall stop
```
اگر مشکل حل شد، باید قانون عبور پورت 8006 را به فایروال اضافه کنید.

### 📜 گام ۴: بررسی گواهی SSL (Certificate)
گواهی‌های منقضی یا خراب در `/etc/pve/local/` مانع شروع `pveproxy` می‌شوند:
```bash
ls -la /etc/pve/local/pve-ssl.pem /etc/pve/local/pve-ssl.key  # وجود فایل‌ها
openssl x509 -in /etc/pve/local/pve-ssl.pem -noout -dates     # تاریخ انقضا
```
برای بازسازی گواهی‌ها:
```bash
pvecm updatecerts --force
systemctl restart pveproxy
```
(ممکن است بعد از این کار نیاز به پاک کردن کش مرورگر یا پذیرش گواهی جدید داشته باشید).

### 💾 گام ۵: بررسی فضای دیسک
پر شدن پارتیشن `/` یا `/var` باعث می‌شود سرویس‌ها بی‌صدا از کار بیفتند:
```bash
df -h
```
اگر فضای آزاد بسیار کم است (نزدیک ۱۰۰٪)، ابتدا با پاک کردن لاگ‌های قدیمی یا کش‌ها فضا آزاد کنید، سپس `systemctl restart pveproxy` را اجرا کنید.

### 🌐 گام ۶: بررسی سمت مرورگر و شبکه
*   **کش مرورگر**: یک **Hard Refresh** بزنید (`Ctrl+Shift+R`) یا در حالت **ناشناس (Incognito)** امتحان کنید. کش مرورگر گاهی با فایل‌های سمت سرور تداخل می‌کند.
*   **بازسازی کش سمت سرور** (در موارد نادر):
    ```bash
    rm -rf /var/lib/pve-manager/
    apt install --reinstall proxmox-widget-toolkit pve-manager
    systemctl restart pvedaemon pveproxy
    ```
*   **بررسی فایل `/etc/hosts`**: مطمئن شوید نام هاست به درستی به IP محلی (مثلاً `127.0.0.1` یا IP اصلی) نگاشت شده است. عدم تطابق می‌تواند سرویس‌ها را مختل کند.

### 💎 جمع‌بندی
با توجه به اینکه SSH و پینگ کار می‌کنند، **سناریوی محتمل** مشکل در **`pveproxy`** (به دلیل خطا، کرش، مشکل گواهی یا فضای دیسک) یا **فایروال** است. اگر مراحل بالا مشکل را حل نکرد، خروجی دستورات زیر را برای بررسی دقیق‌تر بفرستید:
```bash
systemctl status pveproxy --no-pager
journalctl -u pveproxy -n 30 --no-pager
df -h
```
