در لینوکس برای ارائه فایل از طریق iSCSI، استانداردترین و قدرتمندترین روش استفاده از فریم‌ورک **LIO** به همراه ابزار مدیریتی **`targetcli`** است. این ابزار به شما اجازه می‌دهد یک فایل معمولی (مثل `disk.img`) را به عنوان یک دیسک سخت به کلاینت ارائه دهید.

### 📦 گام ۱: نصب پیش‌نیازها
ابتدا باید بسته `targetcli` را روی سرور لینوکس (که نقش Target را دارد) نصب کنید. دستور نصب بسته به توزیع شما متفاوت است:
*   **Debian/Ubuntu**: `sudo apt install targetcli-fb`
*   **RHEL/CentOS/Fedora**: `sudo dnf install targetcli`
*   **Arch Linux**: `sudo pacman -S targetcli-fb`

### 🛠️ گام ۲: پیکربندی از طریق `targetcli`
در ترمینال (با دسترسی root) دستور `sudo targetcli` را اجرا کنید تا وارد محیط شل تعاملی این ابزار شوید. پرامپت به شکل `/>` تغییر می‌کند.

**۱. ایجاد یک فایل بک‌اند (Backstore) از نوع `fileio`**
این دستور یک فایل با اندازه مشخص (مثلاً ۱۰ گیگابایت) در مسیر دلخواه شما ایجاد می‌کند تا به عنوان دیسک مجازی استفاده شود:
```bash
/backstores/fileio create name=my_disk_image file_or_dev=/path/to/your/disk.img size=10G
```
*   `name`: نامی دلخواه برای این آبجکت ذخیره‌سازی.
*   `file_or_dev`: مسیر کامل فایلی که می‌خواهید به اشتراک بگذارید.
*   `size`: حجم فایل (در صورت عدم وجود، ایجاد می‌شود).

**۲. ایجاد یک Target با نام IQN**
یک IQN (نام جهانی iSCSI) منحصربه‌فرد برای سرور خود بسازید. می‌توانید از قالب پیشنهادی استفاده کنید:
```bash
/iscsi create iqn.2026-10.com.example:server.target
```
با این کار، یک Target به همراه یک گروه پورتال پیش‌فرض (معمولاً `tpg1`) ایجاد می‌شود.

**۳. اتصال LUN به Target**
اکنون باید بک‌اند ساخته‌شده در مرحله ۱ را به عنوان یک LUN (واحد منطقی) به Target متصل کنید:
```bash
/iscsi/iqn.2026-10.com.example:server.target/tpg1/luns create /backstores/fileio/my_disk_image
```
این دستور فایل شما را به عنوان یک دیسک قابل ارائه به کلاینت‌ها معرفی می‌کند.

**۴. تنظیم پورتال (Portal) برای شنود**
به صورت پیش‌فرض، Target روی آدرس `0.0.0.0` (همه رابط‌ها) و پورت `3260` گوش می‌دهد. اگر می‌خواهید فقط روی یک IP خاص (مثلاً `192.168.1.10`) شنود کند، دستور زیر را اجرا کنید:
```bash
/iscsi/iqn.2026-10.com.example:server.target/tpg1/portals create 192.168.1.10 3260
```

**۵. مدیریت دسترسی (ACL)**
برای اینکه فقط کلاینت‌های مجاز بتوانند به این Target متصل شوند، باید IQN کلاینت(ها) را به لیست ACL اضافه کنید. IQN کلاینت معمولاً در فایل `/etc/iscsi/initiatorname.iscsi` روی سیستم کلاینت قرار دارد:
```bash
/iscsi/iqn.2026-10.com.example:server.target/tpg1/acls create iqn.2026-10.com.client:myclient
```
> **نکته امنیتی**: هرگز از تنظیم `generate_node_acls=1` (بدون احراز هویت) در محیط عملیاتی استفاده نکنید، مگر برای تست موقت، زیرا هر کلاینتی می‌تواند متصل شود.

**۶. خروج و ذخیره تنظیمات**
با دستور `exit` از محیط `targetcli` خارج شوید. به‌طور پیش‌فرض، تنظیمات به صورت خودکار در فایل `/etc/target/saveconfig.json` ذخیره می‌شود.

### 🔄 گام ۳: فعال‌سازی سرویس برای پایداری
برای اینکه پیکربندی پس از ری‌استارت سرور از بین نرود، باید سرویس `target` را فعال کنید:
```bash
sudo systemctl enable --now target.service
```
این سرویس در هنگام بوت، ماژول‌های کرنل لازم را بارگذاری کرده و پیکربندی ذخیره‌شده را بازگردانی می‌کند.

### 💡 روش جایگزین (سنتی): `tgtadm`
اگر به هر دلیلی نمی‌توانید از `targetcli` استفاده کنید، ابزار قدیمی‌تری به نام `tgtadm` (بخشی از پروژه STGT) نیز وجود دارد. این روش مبتنی بر خط فرمان است و پیچیدگی کمتری دارد اما انعطاف‌پذیری `targetcli` را ندارد. برای مثال، ایجاد یک Target با `tgtadm` به شکل زیر است:
```bash
# راه‌اندازی دیمن
tgtd
# ایجاد یک Target جدید
tgtadm --lld iscsi --op new --mode target --tid 1 -T iqn.2026-10.com.example:server.target
# افزودن یک LUN (فایل) به آن
tgtadm --lld iscsi --op new --mode logicalunit --tid 1 --lun 1 -b /path/to/your/disk.img
```
با این حال، برای اکثر توزیع‌های مدرن، **`targetcli` انتخاب توصیه‌شده و استاندارد است**.
